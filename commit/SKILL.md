# Commit

依据 [Conventional Commits 1.0.0-beta](https://www.conventionalcommits.org/en/v1.0.0-beta/) 描述提交。遵循用户明确要求及仓库的 AGENTS.md、贡献指南和提交校验配置；仓库使用其他版本或约定时按其要求调整，并在有实质差异时说明。

## 确定操作与内容

- 用户只要求生成、修改或检查提交信息时，仅提供文本，不改暂存区或创建提交。单独调用 `$commit` 默认先生成信息；“提交当前改动”等请求已授权相应本地提交，无需重复确认。
- 在目标仓库读取 `git status --short`、`git diff --cached` 和必要的 `git diff`，结合少量近期提交判断语言和范围惯例。生成信息时，有暂存改动默认以暂存区为依据；没有暂存改动则依据用户指定的工作区改动，并说明范围。未跟踪文件需读取内容，不能只凭文件名概括。
- 只对用户指定或本次任务明确涉及的改动操作。混有无关暂存内容时，不直接提交整个暂存区，不擅自撤销用户的暂存；不能可靠隔离范围时再询问。不要用 `git add .` 或 `git commit -a` 意外纳入其他改动。
- 信息必须反映实际差异，不凭任务标题猜测实现结果。不虚构修复效果、测试结果、关联 issue 或兼容性影响。没有代码上下文时，依据用户提供的变更说明起草；信息不足以判断时说明需要什么。

## 提交格式

```text
<type>(<可选 scope>): <简短描述>

<可选正文>

<可选页脚>
```

类型与描述必填；范围省略时连同括号一起省略。冒号后有一个空格。正文与标题、页脚与正文之间各空一行。

| 类型或标记 | 使用条件 | 语义版本含义 |
| --- | --- | --- |
| `feat` | 新增功能 | MINOR |
| `fix` | 修复缺陷 | PATCH |
| `BREAKING CHANGE:` | 对外接口或行为存在不兼容变化 | MAJOR，优先于类型 |

beta 规范强制新增功能使用 `feat`、修复缺陷使用 `fix`，并允许其他类型。以下是实用惯例，不是该规范强制的类型表：

- `docs`：仅文档改动。
- `style`：代码格式、空白等不影响行为的调整；界面视觉改动应按实际意图选择 `feat` 或 `fix` 等类型。
- `refactor`：重构，既不新增功能也不修复缺陷。
- `perf`：性能优化。
- `test`：测试相关改动。
- `build`、`ci`、`chore`：按仓库惯例分别用于构建依赖、持续集成和其他维护。

类型不能替代对兼容性的判断。其他类型本身没有规范强制的版本升级含义；本技能不自动升级版本、创建标签或发布。

## 写出准确的信息

- 使用简洁的小写英文 type；scope 选择仓库已有的模块名称，没有明确范围则省略。
- 描述使用用户指定的语言；否则沿用仓库惯例，无惯例时使用用户当前语言。用具体动作和结果表达，避免“更新代码”“修复问题”一类空泛描述。
- 标题简短但保留必要信息。72 字符等长度限制只有仓库要求时才强制，不把它当作 beta 规范要求。
- 正文只在需要时说明动机、关键行为变化或取舍。页脚仅引用实际已知的 issue 等元信息。
- 破坏性变化在正文或页脚的最开头写 `BREAKING CHANGE: `，后接不兼容之处，已知时补充迁移方式。不能只以标题中的 `!` 代替它：用户给出的 beta 版未规定这种简写。
- 独立目的的改动尽量拆成多个提交；同一功能的实现、测试和文档可以作为一个完整提交。拆分应保留可理解、可验证的边界，不能机械地按文件类型拆分。

示例：

```text
fix(parser): 修复连续空格导致的解析错误
```

```text
feat(config): 支持新版配置格式

BREAKING CHANGE: 不再读取 legacy.json，请将配置迁移到 config.json。
```

## 执行已授权的本地提交

1. 明确要提交的文件或代码块，按需精确暂存；提交前重新核对完整暂存差异，确保没有混入无关改动。
2. 遵循仓库必需的校验，对本次改动运行适当检查；已有有效检查结果可复用。未运行的检查如实说明。
3. 使用准备好的信息创建提交。多行信息优先写入 UTF-8 临时文件，再使用 `git commit -F`，避免 shell 展开或换行转义损坏内容；临时文件不加入提交。
4. 提交失败时先读取错误。不得默认跳过 hooks、关闭签名或反复盲试。校验若修改了文件，应重新检查差异和范围再决定是否暂存重试。
5. 成功后检查最新提交和工作区状态，返回简短哈希、提交标题及实际检查结果；存在剩余改动时说明。

提交授权不包含 push、amend、rebase、reset 或其他历史重写；仅在用户另有要求时执行这些操作。没有目标改动时说明情况，不创建空提交。

## 输出

只生成信息时，提供一个可直接复制的提交信息代码块；只有拆分确有必要时才给多个。检查信息时指出具体不符合之处并给出修正版。完成提交时简洁报告结果，不声称未执行的操作已经完成。
